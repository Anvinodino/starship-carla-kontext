1  Terminal-Grundlagen
Das Terminal ist ein Fenster, in das du Befehle tippst. Öffnen: Strg + Alt + T . Ein weiteres Terminal als Reiter im selben Fenster:
Strg + Umschalt + T .
Befehl / Taste
Bedeutung
pwd
Zeigt, in welchem Ordner du gerade bist.
ls
Listet die Dateien und Ordner im aktuellen Ordner.
mkdir ordner
Legt einen neuen Ordner an.
cd ordner
Wechselt in einen Ordner. cd .. eine Ebene zurück, cd ~ in deinen Home-Ordner.
~
Kurzform für deinen Home-Ordner, hier /home/ieem .
Tab
Vervollständigt Datei- und Ordnernamen. Spart Tippfehler.
Pfeil hoch
Holt den letzten Befehl zurück.
Strg + Umschalt + V
Einfügen im Terminal ( Strg + V allein geht dort nicht).
Strg + C
Beendet das Programm, das gerade im Terminal läuft.
Lange Befehle mit \ am Zeilenende gehören zusammen. Kopiere alle Zeilen auf einmal und füge sie ein.
2  Repository herunterladen
Das Repository enthält beide Bots: 01_Clevon1 und 02_starship_emodell . Es ist öffentlich; eine Anmeldung ist nicht nötig.
2.1 Einmalig: Git und Git LFS
# Prüfen, ob Git und Git LFS da sind (Versionsnummer = installiert)
git --version
git lfs version
# Falls etwas fehlt (fragt nach deinem Passwort):
sudo apt install git git-lfs
git lfs install

2.2 Ordner anlegen und Repository klonen
# Ordner anlegen und hineinwechseln
mkdir -p ~/carla_projekt
cd ~/carla_projekt
# Repository mit beiden Bots holen (Modelldateien kommen über Git LFS mit)
git clone -b clevon-starship-carla-0.10 \
  https://git.ieem-ka.de/rari1014/last_mile-delivery-carla.git
cd last_mile-delivery-carla
git lfs pull
ls
Du solltest 01_Clevon1 , 02_starship_emodell und README.md sehen. Alle weiteren Befehle gehen davon aus, dass das Repo unter
~/carla_projekt/last_mile-delivery-carla liegt. Wer einen anderen Ordner wählt, ersetzt diesen Pfad überall.
# Später: neuesten Stand holen
cd ~/carla_projekt/last_mile-delivery-carla
git pull
git lfs pull

4  Starship in CARLA importieren (nur auf neuem Rechner)
Ist vehicle.starship.bot in CARLA noch nicht vorhanden, baut ein Skript den Bot im laufenden Unreal Editor automatisch auf: Modell,
Kollisionskörper, sechs Räder, Fahrzeug-Blueprint und Anmeldung bei CARLA.
1. Unreal Editor mit dem CARLA-Projekt starten (siehe unten) und warten, bis er offen ist.
2. Im Editor einmalig: Edit → Project Settings → Plugins → Python → Enable Remote Execution anhaken.
3. Import-Skript ausführen.
TERMINAL 1
# Editor starten (Ladezeit einige Minuten)
~/UnrealEngine5_carla/Engine/Binaries/Linux/UnrealEditor \
  ~/CarlaUE5/Unreal/CarlaUnreal/CarlaUnreal.uproject > /dev/null 2>&1 &
# Starship importieren und registrieren (ca. 5-7 min, endet mit SUCCESS)
cd ~/carla_projekt/last_mile-delivery-carla/02_starship_emodell/scripts/unreal_editor/ue5
./build_all.sh
# Bordstein-Assistent anhängen (nur wenn das CARLA-Plugin die Komponente enthält)
python3 ue_remote.py s08_curb_assist_component.py
# Test im Editor: Play starten (beenden mit s07_stop.py)
python3 ue_remote.py s07_play.py
Bordstein-Assistent: Die C++-Komponente liegt unter 02_starship_emodell/unreal/ue5_carla_plugin . Sie muss einmalig in das
CARLA-Plugin kopiert und der Editor neu gebaut werden (10–20 min). Ohne sie fährt der Bot normal, kommt aber nicht auf
Bordsteine. Details: 02_starship_emodell/docs/IMPLEMENTIERUNG_CARLA_0.10.md .
5  CARLA starten und beenden
CARLA ist der Simulator. Er muss laufen, bevor du einen Bot startest. Wähle eine der Varianten. Ein offener Unreal Editor (Kapitel 4) mit Play
geht auch, verbraucht aber mehr Grafikspeicher.

Variante A: mit Fenster, ohne ROS 2
TERMINAL 1
~/UnrealEngine5_carla/Engine/Binaries/Linux/UnrealEditor \
  ~/CarlaUE5/Unreal/CarlaUnreal/CarlaUnreal.uproject \
  /Game/Carla/Maps/Town10HD_Opt -game -windowed \
  -ResX=1280 -ResY=720 -quality-level=Low -prefernvidia
Variante B: mit Fenster und ROS 2
TERMINAL 1
~/UnrealEngine5_carla/Engine/Binaries/Linux/UnrealEditor \
  ~/CarlaUE5/Unreal/CarlaUnreal/CarlaUnreal.uproject \
  /Game/Carla/Maps/Town10HD_Opt -game -windowed \
  -ResX=1280 -ResY=720 -quality-level=Low -prefernvidia --ros2
Variante C: ohne Fenster, mit ROS 2 (spart Grafikspeicher)
TERMINAL 1
~/UnrealEngine5_carla/Engine/Binaries/Linux/UnrealEditor \
  ~/CarlaUE5/Unreal/CarlaUnreal/CarlaUnreal.uproject \
  /Game/Carla/Maps/Town10HD_Opt -game -RenderOffScreen \
  -quality-level=Low -prefernvidia --ros2
Warten: Der Start dauert 1–3 Minuten. Wichtig: --ros2 mit zwei Bindestrichen, sonst bleibt ROS 2 aus. Beenden: im Terminal 1
Strg + C , vorher alle anderen Programme beenden.
# Läuft CARLA? (in einem neuen Terminal)
~/CarlaUE5/.venv/bin/python -c "import carla; c=carla.Client('localhost',2000); \
c.set_timeout(5); print('CARLA läuft:', c.get_world().get_map().name)"

7.4 Prüfen, ob Daten ankommen
TERMINAL 5

ros2 topic hz /carla/starship/starship_gnss           # Rate (ca. 5 Hz), Strg+C
ros2 topic echo --once /carla/starship/starship_gnss  # eine Nachricht
ros2 run tf2_ros tf2_echo map starship                # Position des Bots
7.5 Über ROS 2 steuern
Nur mit einem Bot aus spawn_starship.py ; ein laufender Fahrclient überschreibt die ROS-Befehle.
TERMINAL 5
source ~/carla_projekt/last_mile-delivery-carla/02_starship_emodell/Sensorik/ROS2/ros_ws/setup.bash
# Geradeaus fahren (sendet 10x pro Sekunde, Strg+C beendet das Senden)
ros2 topic pub -r 10 /carla/starship/vehicle_control_cmd \
  carla_msgs/msg/CarlaEgoVehicleControl '{throttle: 0.7}'
# Linkskurve (steer: -1 = links, +1 = rechts)
ros2 topic pub -r 10 /carla/starship/vehicle_control_cmd \
  carla_msgs/msg/CarlaEgoVehicleControl '{throttle: 0.6, steer: -1.0}'
# Anhalten (einmalig senden, wartet auf die Verbindung)
ros2 topic pub --once -w 1 /carla/starship/vehicle_control_cmd \
  carla_msgs/msg/CarlaEgoVehicleControl '{brake: 1.0}'
Kein Not-Halt: Hörst du mit dem Senden auf, fährt der Bot mit dem letzten Befehl weiter. Zum Anhalten immer ausdrücklich den
Bremsbefehl senden.

10  ROS-2-Demo: Slalom fahren (beide Bots)
Für Vorführungen: Ein Skript setzt den Bot an eine lange gerade Straße, lenkt ihn über ROS 2 im Slalom (Topic vehicle_control_cmd ) und
zeigt zwei Fahrzeugkameras aus den JSON-Sensorprofilen, deren Bilder es selbst über ROS 2 empfängt: beim Starship Frontkamera K1

und Heckkamera K8, beim Clevon Front- und Heckkamera. Position, Sichtfeld und Rate entsprechen dem Profil. Über jedem Bild steht das
ROS-Topic. Am Ende der Geraden setzt das Skript den Bot an den Start zurück; die Kamera im CARLA-Fenster folgt ihm.
Voraussetzung: CARLA mit --ros2 und Fenster (Kapitel 5, Variante B) und Kapitel 3.3. Kein anderer Fahrclient für diesen Bot darf laufen.
Auch für den Clevon im Starship-Ordner bleiben! Das Demo-Skript und sein ros_ws liegen nur unter
02_starship_emodell/Sensorik/ROS2 . Das Skript steuert beide Fahrzeuge; den Clevon wählst du mit --vehicle clevon . Im Ordner
01_Clevon1/Sensorik/ROS2 gibt es weder ros2_slalom_demo.py noch ros_ws/build.sh (Fehler No such file or directory).
TERMINAL 2
# immer im Starship-Ordner, auch für den Clevon

# Starship (ca. 5 km/h):

11  Probleme und Lösungen
Meldung / Verhalten
Lösung
No such file or directory
Falscher Ordner oder Tippfehler. Mit pwd und ls prüfen, die cd -Zeile erneut einfügen.
ros2_slalom_demo.py oder ros_ws/build.sh nicht
gefunden (Clevon)
Die Demo liegt nur im Starship-Ordner: cd …/02_starship_emodell/Sensorik/ROS2 ,
dann --vehicle clevon .
time-out ... while waiting for the simulator
CARLA läuft noch nicht oder lädt noch. Warten, Test aus Kapitel 5.
get_trafficmanager ... std::exception
Ein alter Fahrclient läuft noch: alle Terminals mit Strg + C beenden oder pkill -f
manual_control .
Out of memory on Vulkan , CARLA stürzt ab
Grafikspeicher voll. Weniger Kameras, --preview , Variante C. Kein zweites CARLA und
keinen Editor parallel.
Keine ROS-Topics
CARLA ohne --ros2 gestartet oder source …/setup.bash vergessen. Im CARLA-Log
muss „ROS2: Enabling ROS2“ stehen.
Package 'carla_msgs' not found
Kapitel 3.3 ausführen und vor dem Befehl source …/ros_ws/setup.bash .
Bot reagiert nicht auf ROS-Befehle
Läuft noch ein Fahrclient? Bot mit spawn_starship.py bzw. spawn_clevon.py neu
setzen.
No module named 'carla' oder 'yaml'
Immer ~/CarlaUE5/.venv/bin/python verwenden; für yaml Kapitel 3.2.
NO_EDITOR_FOUND beim Import
Editor noch nicht fertig geladen oder Remote Execution nicht aktiviert (Kapitel 4).
vehicle.starship.bot nicht gefunden
Starship noch nicht importiert: Kapitel 4.
Alles hängt
Alle Programme beenden, notfalls pkill -f UnrealEditor und CARLA neu starten.
Reihenfolge beim Beenden
1. Sensoranzeigen und ROS-Programme: Esc bzw. Strg + C (Sensoren werden entfernt).
2. Fahrclient: Esc .
3. CARLA: im Terminal 1 Strg + C .
